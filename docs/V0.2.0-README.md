# ArunikaDungeon 0.2.0 — Smart Configuration & Automatic Migration
Development preview for Paper 1.21.11 / Java 21. Source release; Paper runtime NOT validated. Gameplay remains hard-disabled. Keep CdrDungeonSpawner, ArunikaDungeonExchange, CdrWaystone and CdrWaystoneBedrock unchanged. This version deliberately does not take ownership of their commands or databases.

## New in 0.2.0
- Automatically initializes five starter dungeon folders and separate Shared/Private settings and wave/boss drop tables. Templates have empty arena coordinates, empty loot lists and placeholder wave mob lists; enablement is not playable in this version.
- Detects additional canonical dungeon folders, creates new ones via `/adg create`, checks unique IDs/floor numbers. Adding waves creates missing drop files; reducing waves retains their old files.
- Schema 1 to 2 smart merge preserves existing values and unknown keys, and skips writes to semantically unchanged files. Changed YAML may be reformatted and comments lost; originals are backed up byte-for-byte.
- Validation of schema, identity, waves, drop amount/chance/type, entry rules and basic arena fields. Runtime registry resolution (MythicMobs IDs, material IDs, world existence and arena safety) belongs to future engine work.
- Atomic individual file replacement, transaction journal, rollback on write failure and recovery before the next load after interrupted migration. Filesystem must support atomic rename; unsupported filesystems fail rather than use unsafe replacement. No guarantee against filesystem-level power-loss corruption; external backups remain prudent.
- Automatic config backup retention defaults to 5; only managed auto-* backups pruned. Config migration never writes to old plugin directories. Do not edit YAML during reload/update.
- Isolated foundation database schema 2 migration with pre-migration SQLite snapshot and SQL transaction. Production JDBC path has not been executed here. Offline legacy preservation tool retained.
- `/adg reload <id>` revalidates catalog globally and restricts migration writes to the chosen dungeon; if other files need migration, use `/adg reload all`. Catalog/global metadata is refreshed; gameplay snapshots are a future task. Failure retains current in-memory catalog. Config edit jobs execute off the main thread, initial load happens during enable.
- Old thread-safe session tests and API preserved, including independent Shared cooldown (still in memory), UUID exclusivity and Private cap.

## Commands (source implementation, not Paper runtime tested)
`/adg status`, `/adg legacy`, `/adg help`, `/adg create <id> <floor> [display name]`, `/adg reload [all\|id]`. All require `arunika.dungeon.admin` (OP default). No player entry or reward processing. `/dg`, `/opdg`, `/cds`, `/cws` remain owned by old plugins. No Waystone JAR update in this phase.

## Build and verify
Install Java 21 and Maven 3.9+ with internet access. Windows:
```
powershell -ExecutionPolicy Bypass -File tools/build-verified.ps1
```
Linux/macOS:
```
bash tools/build-verified.sh
```
Scripts run Maven package, actual SnakeYAML tests and SQLite JDBC migration test. Expected JAR: `target/ArunikaDungeon-0.2.0.jar`. If a test fails do not install it. Those scripts have not been run successfully here because Maven/Paper API/SnakeYAML/SQLite JDBC dependencies are unavailable and DNS resolution to repositories failed. No fake API stubs or incomplete plugin JAR are supplied. The JAR is only a development preview even after standalone tests pass.

## Executed verification
`bash tools/test-core.sh /path/to/offline/legacy/plugins`: 22 core tests passed against archive copy.
`bash tools/test-config.sh`: 33 schema/transaction tests passed using a test-only serialized fixture codec (not real YAML). Production SnakeYAML codec and Paper adapter remain uncompiled here. See docs/CORE-TEST.txt and docs/CONFIG-TEST.txt.
`python tools/import_legacy.py --plugins /path/to/offline/plugins --output /path/to/new/staging --server-stopped`: rerun passed for original archive copy, preserving 113 transactions, 109 purchases and 32 stock rows; 22 input files checked. This is offline staging only, not production migration/cutover.

## Staging installation / updating
1. Use separate Paper 1.21.11 test server. Keep all legacy plugins and their configs. Build and pass the scripts above first.
2. Stop Paper; replace only the ArunikaDungeon JAR (if installed); keep ArunikaDungeon folder. Restart (never /reload). On first boot generated files appear under plugins/ArunikaDungeon.
3. Check `/adg status` (DB ready, five or more floors, entry disabled), inspect generated YAML and backups. Try `/adg create dragon 6 Dragon King`. Increase a dungeon's wave-count and `/adg reload <id>`; check custom configs preserved. Confirm legacy commands/Waystones unaffected.
4. Check Paper console and Java/Bedrock client for errors. Do not expose Phase II to players yet. Stop server and remove only the new JAR if problems arise; keep old plugins.
5. If repairing config, use originals in backups/auto-*/original/. If rolling back the release to v0.1.0, restore matching schema 1 config and foundation database backup while server is stopped; old release must refuse newer schema. Never blindly downgrade.
