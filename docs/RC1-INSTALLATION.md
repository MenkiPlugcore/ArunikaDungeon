# Guardian Awakening RC1 — staging installation

## 1. Build (required before installing)
- Extract source, install Java 21 and Maven 3.9+; verify `java -version`, `mvn -v`.
- Windows: `powershell -ExecutionPolicy Bypass -File tools/build-verified.ps1`.
- Linux: `bash tools/build-verified.sh`.
- GitHub: upload source contents including `.github/workflows/build.yml` into your own repository and run **Verified dependency build** in Actions. Do not use the artifact if the workflow fails. On success the staging artifact contains the JAR. This is an alternative to local build, not runtime verification.
- Expected output `target/ArunikaDungeon-1.0.0-RC1.jar`. The local environment used for this delivery did not have Maven or repository DNS. Do not bypass failed tests or use a stub build.

## 2. Staging preparation
1. Stop a separate staging instance, never production. Make a full backup of server worlds, playerdata, plugin data and databases (including WAL/SHM), inventories and permission/economy stores. Restore only as a consistent snapshot. Keep old Waystone binaries, configs and resource packs. Do not downgrade a ticket ledger containing EXPOSED records.
2. Use Paper 1.21.11 with Java 21. Install actual MythicMobs, CdrWaystone and CdrWaystoneBedrock used on Arunika; for their features retain LuckPerms, Geyser/Floodgate, Nusa Karsa, MMOItems/ItemsAdder and dependencies. Do not run PlugMan or /reload. The original four JARs are not bundled, and no source of Waystone was reconstructed.
3. First boot shadow mode with the old plugins present; inspect `/adg status` and `/adg legacy`. RC1 logs detected versions, preview and module states. Stop. Only on the staging clone, remove old CdrDungeonSpawner JAR before enabling battle, and old ArunikaDungeonExchange JAR before enabling unified Exchange; leave both folders and DBs intact. If the old JARs are present, corresponding modules stay locked. Keep CdrWaystone and CdrWaystoneBedrock installed. Never run dual transaction engines.
4. On startup the generated folder is `plugins/ArunikaDungeon/`. Smart config migration inserts missing settings, retains custom values and backs up affected files. Inspect console; stop on any validation, DB or reflection error. Never delete data/tickets, data/shared-cooldowns.txt or exchange/live. On an existing preview copy, keep all data.
5. Offline optional migration rehearsal (not a cutover): `python tools/import_legacy.py --plugins /path/to/stopped/plugins --output /path/to/new/snapshot --server-stopped`. New Exchange imports its own legacy copy at startup; do not overwrite its live directory with the rehearsal output. Inspect `/opdg status` and `/opdg rewards` before enabling. Original archive counts: 23 configured active rewards, 113 transactions, 109 purchases, 32 stock rows. Counts on the live server may have changed since that archive.

## 3. Configure the first floor
- Keep `foundation-only: true`, and all preview flags off while setting up. Use a dedicated test world and independent WorldGuard protection. The generated YAML is intentionally inactive; it is not a ready-made arena or a real boss pack. Five floor IDs: queen_bee, mega_warden, the_doom, goblin, skeleton.
- `/adg admin` or `/adg setup arena queen_bee shared_1 shared`. Capture corners, player spawn, minion spawn(s), boss spawn, exit. Resume by `/adg setup resume`. Save. Repeat for `private_1 private`, in a separate nonoverlapping region. For gateway, each exit must equal exactly the configured hub point. Make sure relevant worlds and spawn chunks are loaded. Legacy `arena.yml` is preserved; the battle engine uses `battle.yml`. Leave the older floor `settings.yml enabled: false` field alone unless you intentionally configure its legacy requirements.
- Configure real Mythic IDs with `/adg setup wave queen_bee 1 ActualMinionID 8` (replace placeholder with registered ID), repeat for waves 2 and 3, then `/adg setup boss queen_bee ActualBossID` and `/adg setup enable queen_bee`. Use `/adg setup count` when changing wave count; disable the battle before editing. See ADMIN-GUIDE.md for append-wave and setup. No invented IDs are valid until confirmed in MythicMobs.
- Set config.yml `battle-preview: true`; restart. Test `/adg preview start queen_bee shared_1` with a tester in survival/adventure, no flight. Direct preview is admin-only and does not generate real loot or ticket costs. Once basic battles work, enable `shared-preview: true` and `private-preview: true`. `loot-preview: true` only after low-value items and isolation are verified. Public entry remains disabled.

## 4. One Waystone gateway
- Keep original CdrWaystone 0.7.1 and CdrWaystoneBedrock 0.2.1 as audited versions. Install a dedicated permanent admin stone at the hub, hidden and unbound from the legacy dungeon network; do not change player stones. Target it and `/adg gateway` to retrieve UUID. Use actual UUID, coordinates and enabled mode in `integrations/waystone.yml`. Optional return stones must be inside the mapped arenas. See WAYSTONE-GUIDE.md for the exact schema. Restart or `/adg reload all` while no sessions/queues/parties/pending returns exist.
- Grant only testers: `arunika.dungeon.gateway.test`, `arunika.dungeon.shared.test`, `arunika.dungeon.private.test`, `cdrwaystone.use`, `cdrwaystone.dungeon.use`. Grant `arunika.dg.use` and **`arunika.dungeon.exchange.test`** for Exchange. `arunika.dungeon.admin` and `arunika.dg.admin` are staff permissions, not player permissions. If Bedrock anchor click fails, look at the registered anchor and use `/adg gateway open`. There is no remote entry bypass.
- Shared is free, no dungeon participant cap, 30-min cooldown per floor after boss death. Private costs one universal ticket per party (1–5), no Vault payment. `/adg ticket give PlayerName` issues a test ticket when Private is active. The leader holds a valid ticket in main hand; invite/ready via hub GUI. One session per player.

## 5. Loot, Exchange, Nusa Karsa
- Reward tables: `dungeons/<floor>/shared\|private/wave-N-drops.yml` and `boss-drops.yml`. Physical free-for-all. Default pickup 3s, final loot 45s. Configure low test drops in GUI or `/adg loot addhand ...`; `/adg reload all` applies edits. See LOOT-GUIDE.md. EXPOSED ticket status prevents refunds after reward exposure.
- Exchange locked by default. Once migration verified and old Exchange absent on staging, `/opdg ticket 50 on` sets adjustable token price; `/opdg exchange on` enables test transactions. `/dg` catalog, `/opdg tx list` audit pending. No blind retry or automatic refund on ambiguous crash. See EXCHANGE-GUIDE.md. Do not change the old token template without a deliberate currency migration. Keep all permission allowlists narrow.
- `integrations/nusa-karsa.yml`: disabled initially. Optional Class XP (not separate Race XP) and explicitly registered provider; native command version guard targets audited 1.2.10. No change to formulas, no artificial Awakening progress. Test rune, forge, legendary skill, summons and pet interactions before enabling bonuses. See NUSA-KARSA-AUDIT.md.

## 6. Release gates and rollback
See RC1-AUDIT.md. Do not treat a successful compiled JAR as production-ready. Check Java and Bedrock clients, all session/teleport/inventory/migration/crash scenarios, and profile with spark before approving rollout. If anything fails, stop staging and restore the consistent pre-test snapshot; do not overwrite live databases with stale backups or mix an old JAR with new ledger data. For production migration, take fresh backups and plan downtime only after runtime acceptance tests pass.
