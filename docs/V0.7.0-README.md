# ArunikaDungeon v0.7.0 — Unified Dungeon Exchange
Development source preview for Paper 1.21.11 / Java 21, based on exact v0.6.0 ZIP. No installable plugin JAR verified. Do not replace production plugins yet.

## What's new
- Automatic one-time import of the old Exchange config, reward YAML and SQLite database (including WAL). Original folder is never opened for write; raw originals copied under `exchange/live/legacy-original`. Existing migrated data is not overwritten. Migration starts only when old plugin is absent, so no dual ownership. Preserve UUID, revision, cost, stock, purchase limit, purchase history, transaction rows, and raw token/item serialization.
- Unified Exchange staging commands `/dg`, `/opdg` (legacy owner priority), plus fallback `/adg exchange` and `/adg exchange admin ...`. Native inventory catalog, category cycling, pagination and explicit confirm/cancel; Java + Geyser Bedrock intended, runtime untested. Command-based admin editor with atomic save and backup.
- One universal ticket reward at configurable token price (example default 50, initially disabled). Uses v0.5+ serial ledger; ticket serial is the purchase transaction UUID. Same copy never redeems twice. Claim on full inventory/offline via `/dg claim <serial>`; no repeat issue after claim.
- Old item rewards use exact serialized template. Old permission rewards preserve their metadata and implement duration/duplicate rejection via LuckPerms API, gated by opt-in allowlist. PERMISSION icons are not awarded as items (matching old behavior). COMMAND/BUNDLE rewards remain locked; none were present in audited catalog.
- Single bounded worker owns SQLite, prepared statements, WAL, full synchronous durability, per-player in-flight lock and durable reservation state. Stock and purchase counts reserve atomically. Main thread revalidates inventory then applies debit/reward; no automatic replay after ambiguous crash. Admin must verify pending transactions. No guarantee of atomicity across Paper playerdata, SQLite and LuckPerms. Legacy token is stackable and exact `isSimilar` matching; not an individually serialized anti-dupe currency, external exploits require separate mitigation.
- Preserves v0.6.0 battle, queue, loot, party, and config engine. Production gateway remains disabled.

## Build / validation
Run `bash tools/build-verified.sh` or Windows `powershell -ExecutionPolicy Bypass -File tools/build-verified.ps1` with Java 21, Maven and dependency access. Expected JAR: `target/ArunikaDungeon-0.7.0.jar` after successful build. Real dependency and server smoke test required. See `docs/BUILD-STATUS.txt` and `docs/EXCHANGE-GUIDE.md`.

Do NOT remove any old plugin on production. Test on a separate clone: stop it, keep backup + original folder, remove only legacy Exchange JAR from clone (not the folder), start the newly built plugin, check migration and then deliberately enable transactions. Do not roll back to old DB after new transactions; reconcile in maintenance first.
