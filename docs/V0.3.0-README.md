# ArunikaDungeon 0.3.0 — Arena, Wave & Boss Engine
Development source release from v0.2.0. Target Paper 1.21.11 / Java 21 / MythicMobs 5.12.1. Public entry stays hard-disabled; optional admin-only battle preview requires isolated test world. No plugin JAR supplied: real Paper dependencies unavailable here. Do not install on production before build and staging validation.

## Changes
- Immutable per-floor battle snapshots; multiple reusable independent arenas with explicit bounds, minion spawn points, boss point, and exit. Reject overlapping arenas, unsafe coordinate definitions, duplicate arena IDs, or exit in any arena.
- Battle state machine PREPARING -> WAVE (1..N) -> BOSS -> COMPLETED or FAILED. Waves advance only after all pending spawns plus tracked live mobs are exhausted; missing/despawned mobs fail, never count as a kill. Timeout, elimination, shutdown and spawn failure clean up owned directly tracked entities and session locks. One Shared session per floor; Private arena reservation isolated. Existing Shared 30 minute cooldown starts at boss death; retained on config reload; restart persistence is v0.4.0 work.
- One centralized battle scheduler with global tracked entity budget (default 100, includes bosses), spawn allowance (default 5 per scheduler pass, at most one per session per pass), rotating order, minion count scaling with cap, TPS/MSPT guard pauses new spawns. No scans of world entities, no cloning/forced synchronous chunk loading. Direct spawn points must already be loaded; missing chunk causes preview rejection/failure. All world/entity operations on server thread. These are architectural optimizations, not measured RAM/TPS improvement.
- Optional MythicMobs public API bridge via reflection; checks IDs and resolves spawn method before preview. Actual boss level 1, stats remain configured in MythicMobs; no direct HP scaling. Actual spawn behavior and custom mechanics not verified here.
- Paper battle adapter source: bossbar health/wave information, actionbar updates once per second, player boundary/teleport, block break/place, basic direct damage and PvP rules, tracked projectile cleanup. Death/quit eliminates current preview player; tries exit on respawn/join. No live reconnect grace in this milestone. Only in-memory pending exits, must use dedicated staging world. Full custom summons, skill/projectile bypass, drop interception (including Mythic custom drop callbacks), arena protection, persistence and crash recovery are not guaranteed yet. Use test mobs without loot/summon/destructive skills and WorldGuard on staging.
- v0.2 folder generation, smart merge, migration journal, rollback, backups, separate Shared/Private loot tables, legacy importer, data preservation and prior commands remain. New optional `battle.yml` per dungeon automatically created with defaults disabled. Config schema stays 2 (additive changes); reload refused during active sessions or pending returns. Do not modify live YAML while migration running. Legacy `arena.yml` kept untouched; actual preview arena layout resides in `battle.yml`.
- No transaction, real ticket, loot engine, public queue, Waystone updates or takeover of `/dg`, `/opdg`, `/cds`, `/cws`. Keep legacy plugin JARs/data installed. `/adg` remains admin-only. `DungeonGatewayApi.entryEnabled()` stays false.

## Build
Install JDK 21 and Maven with internet. Windows: `powershell -ExecutionPolicy Bypass -File tools/build-verified.ps1`. Linux: `bash tools/build-verified.sh`. Build target `target/ArunikaDungeon-0.3.0.jar`. Scripts run regression, battle tests, real SnakeYAML test and SQLite JDBC test. Build alone is not a Paper runtime test. No fake Paper API stubs or standalone JAR labeled as plugin.

## Admin preview (ONLY on isolated staging after successful build)
1. Stop test server, copy only ArunikaDungeon JAR, keep folder and legacy plugins. Restart; `/adg status`. Ensure MythicMobs installed. Never use /reload.
2. Configure `waves.yml`, `boss.yml` and `battle.yml` per floor as described in `docs/BATTLE-GUIDE.md`. Set `config.yml` `battle-preview: true` while keeping `foundation-only: true`. Other players cannot enter through Waystone. Example IDs/coordinates must be replaced; no guessed live locations.
3. `/adg reload all`. Enter the prebuilt staging arena manually with admin testers; ensure spawn/exit chunks loaded. `/adg preview start queen_bee shared_1 [adminName...]`. No ticket or loot engine. Use a non-valuable test mob. Monitor console and `/adg preview status`. `/adg preview stop <session UUID>` aborts. `/adg preview point` prints location for manual copy. `/adg preview exit` retries pending exit. Existing `/adg create`, `/adg reload`, `/adg legacy`, `/adg help` remain.
4. Validate Mythic boss health, actual death callbacks, cleanup, no cross-session damage, no old-plugin effects, and Java/Bedrock clients. Stop and remove new JAR if problems; do not delete legacy folder. Use staging backup if config migration must be reverted.
