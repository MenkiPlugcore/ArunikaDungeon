# ArunikaDungeon 0.9.5 — targeted audit, security and performance
Base: exact v0.9.0 source ZIP, Java 21. Original Waystone/Bedrock and legacy binaries untouched. Staging only, foundation-only remains enforced. No live server or timings available.

## Changes
- SessionRegistry: preserve unexpired cooldown timestamps for temporarily absent valid floor IDs. Re-adding a floor cannot reset its cooldown. Old timestamp format unchanged.
- BattleEngine: O(1) pending-wave count, direct arena permission/overlap queries rather than copied active-arena maps and per-player temporary lists. Linkage errors during cleanup do not stop cleanup of subsequent tracked mobs. Existing global spawn budget, batch, wave rules and no world cloning preserved.
- Paper battle adapter: protect configured arenas even without gateway when battle preview is running. Direct admin test start now performs authorized teleport rather than requiring entry into protected empty arena. Recovery uses configured hub or arena exit. Refuse flying/creative/spectator participants; prevent relevant mode/flight changes during sessions. Only use the launch-session association of tracked projectiles, remove it after hit processing; direct damage must originate from an active player present in that arena. Bossbar removes offline/eliminated viewers and updates on phase transitions. Single sampled TPS/MSPT per battle tick for spawn, progression and queue polling. No new periodic tasks or chunk force-loading added; spawn/exit still require loaded chunks; large teleports remain synchronous and require runtime testing. No boss HP scaling introduced.
- Ticket ledger: pending claim is usable only by claimant until acknowledged (still tradeable after acknowledgement). Refuse symlink ticket records/directory. New durable EXPOSED state before first physical reward candidate or bonus RPG dispatch; EXPOSED cannot refund even after restart, can complete normally. One extra durable write per rewarding Private session, not per mob; failure blocks reward. For safety, a candidate that fails after the exposure marker may still forfeit refund. Legacy records still load; do not downgrade old JAR after EXPOSED is written. No retroactive detection of historical SPENT sessions' rewards. Admin recovery remains manual for old unresolved SPENT. Entire inventory/database/provider chain is not atomic.
- Loot: empty tables reused, cleanup iterates tracked items rather than copying whole map. Current unified Exchange token provided by loaded catalog instead of stale YAML cache; legacy owned token loaded lazily once (reload required after legacy template edit). Physical loot remains free-for-all among registered eligible participants; no personal loot. Serialized ticket prohibition, item budget, session tags and pickup restrictions preserved.
- Exchange: verified stock restore cannot exceed configured stock, cancel requires actual purchase decrement and matching finite/unlimited row, else rollback. Lock access while in a private party. Delay direct delivery of purchased ticket until eligible; claim available later. SQLite worker drains accepted jobs and closes connection at termination rather than submitting close to a potentially full queue. No automated replay for ambiguous debit/delivery. Bounded executor and WAL retained. Permission/provider calls and Bukkit player saves still need live crash/restart tests.
- Nusa Karsa: both external provider and native Class XP now use same bounded 512-entry queue with one dispatch per healthy battle scheduler cycle. External service identity rechecked before dispatch; no native fallback when provider changes; no replay. Preserve native 1.2.10 command exact version guard and native awakening event rules. No new Race XP API, no damage/stat formulas, no fake Awakening progress. Legendary, rune, forge, summoned skills still need real plugin compatibility tests.
- GUI: neutral bottom navigation frame in gateway/admin, single deferred click per menu in all three GUIs, respect pre-cancelled clicks, same 54-slot native inventory layout (Geyser translation not tested). No new assets or scheduler. Admin wave/boss IDs still entered through commands, no complete visual item editing rewrite.
- Configuration: existing smart migration remains; attempt directory fsync after atomic write when platform allows. No default YAML-schema reset or legacy overwrite. Back up before cutover and do not downgrade new ticket records.
